Lernumgebungen mit dem Agenten bereitstellen

Sie beschreiben die Maschine in einer YAML-Datei und erstellen sie mit einem Befehl, auf KubeVirt genauso wie auf AWS. Auf dieser Seite stellen Sie die Befehle zusammen und kopieren sie ins Terminal. Hintergründe stehen in der Lernunterlage zur Schulung.

  1. DefinitionEine YAML-Datei beschreibt die Maschine.
  2. AgentPrüft die Definition und führt den Auftrag aus.
  3. PlattformKubeVirt auf dem lokalen Server oder AWS.
  4. MaschineBereit, sobald der Testdienst antwortet.

    Ablauf für eine Lektion
    
  
    Für eine Lektion mit einer Testmaschine gehen Sie so vor.
    
  
      
  
      Die Plattform geben Sie nur bei create an, die übrigen Befehle lesen sie aus dem gespeicherten Zustand. Eine kurze Hilfe zu jedem Befehl zeigt zum Beispiel python -m agent reset --help.
      

      


      
  
      Den Status lesen
      
  
      status --name zeigt, was der Agent gespeichert hat, und fragt gleichzeitig die Plattform nach dem aktuellen Zustand. Adresse, Ports und Kennung im Beispiel sind Platzhalter.
      
  
      Zeile in der AusgabeBedeutung
      
  
      Eine laufende VM heisst noch nicht, dass die Lernenden arbeiten können. Massgebend ist die Zeile HTTP-Dienst.
      
  
      Zugang in die Maschine
      
  
      Den Zugang öffnen Sie vom Agentenhost aus, Host und Port stehen in der Zeile SSH: ssh -i <privater Schlüssel> -p <Port> ubuntu@<Host>. Auf AWS gilt Port 22, dort entfällt -p <Port>. Nach einem Reset können sich Adresse und Port ändern.
      

      


      
  
      
    
      Mehrere Maschinen als Gruppe
      
    
      Mit --count entstehen mehrere gleiche Maschinen. Aus --name klasse --count 3 werden klasse-1, klasse-2 und klasse-3, auf KubeVirt mit --parallel auch gleichzeitig.
      
    
      Mit derselben Anzahl gelten status, reset und delete für die ganze Gruppe. Reset und Abbau bearbeiten die Maschinen dabei nacheinander. Eine einzelne Maschine sprechen Sie mit ihrem vollen Namen an.
      
    
      Bricht eine Gruppe ab, nennt die Meldung eine gemeinsame Kennung. Mit ihr setzt derselbe Befehl die ganze Gruppe fort.
      
  
      
  
      

      


      
  
      Wenn etwas nicht klappt
      
  
      Bricht ein Befehl ab, lesen Sie zuerst mit status --name den Zustand. Danach lässt sich der Auftrag fortsetzen, ohne dass eine zweite Maschine entsteht.
      
  
      SituationVorgehen
      
  
      Wichtig: Löschen Sie Maschinen nie direkt in KubeVirt oder AWS, sondern immer mit delete. Sonst stimmt der gespeicherte Zustand nicht mehr mit dem tatsächlichen Bestand überein.
      

      


      
  
      Grenzen des Proof of Concept
      
  
      Die Maschinen enthalten Ubuntu und den Testdienst, aber noch keine Modulsoftware. AWS läuft im AWS Academy Learner Lab, dessen Sitzungen zeitlich begrenzt sind. Bevor der Agent im Unterricht eingesetzt werden kann, müssen Zuständigkeiten, Berechtigungen und das Aufräumen nicht mehr benötigter Maschinen geregelt sein.
