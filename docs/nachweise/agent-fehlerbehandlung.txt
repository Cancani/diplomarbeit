Grundlage sind die vom Diplomanden übermittelten Terminalausgaben auf dem
lokalen Zielsystem zum Code-Stand 4aaa29b. Dies sind Entwicklungsprüfungen,
keine formale Messserie und keine Expertenabnahme.

Die JSON-Zeilen sind auf entscheidende Felder gekürzt. Ressourcenlisten,
konkrete Ressourcen-UIDs, Zugangsangaben und lokale Speicherpfade sind
entfernt. Zeitstempel, Ereignisse und Auftragskennungen bleiben erhalten.
Die Kürzungen verändern die ursprünglichen Nachweisdateien anderer Versuche nicht.

Testverfahren für die Antwortverzögerung

Im aktivierten Python-Umfeld aus dem Repository-Verzeichnis wurde folgender
Code über python - ausgeführt. Die Konfiguration wurde nur im Arbeitsspeicher
geändert. Für eine erneute Prüfung muss eine neue Operationskennung gewählt
und für Timeout-Aufruf sowie Fortsetzung identisch verwendet werden. Die
Umgebung muss vorher bereit sein. Der Aufruf beginnt einen echten Reset.

import sys
from adapter.kubevirt_manifest import NAMESPACE, resource_name
from adapter.vertrag import AdapterError
from agent.konfiguration import load_config
from agent.lebenszyklus import reset

adapter_code = r'''
import sys
import time
from adapter.kubevirt import create_server
from adapter.kubevirt_lifecycle import KubeVirtLifecycle
from gemeinsam.prozessschutz import adapter_guard

class DelayedDelete(KubeVirtLifecycle):
    def _request(self, verb, arguments, deadline, *args, **kwargs):
        result = super()._request(verb, arguments, deadline, *args, **kwargs)
        if verb == 'delete' and arguments[:2] == ['--raw', sys.argv[1]]:
            print('TEST: VM-Löschaufruf bestätigt; Antwort wird verzögert.',
                  file=sys.stderr, flush=True)
            time.sleep(45)
        return result

with adapter_guard():
    create_server(DelayedDelete(['microk8s', 'kubectl'], 15)).run(
        transport='stdio')
'''

config = load_config('agent/beispiele/konfiguration.yaml')
target = (
    f'/apis/kubevirt.io/v1/namespaces/{NAMESPACE}/virtualmachines/'
    f'{resource_name("s2-kv-01")}'
)
adapter = config['adapters']['kubevirt']
adapter.update(command=sys.executable, args=['-c', adapter_code, target], timeoutSeconds=30)
try:
    reset(config, 's2-kv-01', 'reset-s2-kv-06', 1200)
except AdapterError as error:
    print(f'Test beendet mit Fehlercode: {error.code}', flush=True)
    raise SystemExit(1)
else:
    raise SystemExit('Kein Timeout ausgelöst; Testziel nicht erreicht.')

Danach wurden mit der normalen Beispielkonfiguration status und reset für
denselben Lauf und dieselbe Operationskennung aufgerufen. Die Fortsetzung
verwendete --timeout-seconds 1200.

Aussagegrenze

Die Verzögerung liegt nach der bestätigten Kubernetes-Annahme und vor der
MCP-Antwort an den Agenten. Der Versuch belegt keine beliebigen Netzfehler
oder das harte Ende eines noch laufenden kubectl-Unterprozesses. Die
Wiederaufnahme nach hartem Agentenende wurde auf KubeVirt während des
Abbaus geprüft. Erstellungsantworten, verbliebene Adapter und veraltete
Sitzungen sind zusätzlich in automatisierten Tests mit Testbeständen geprüft.
